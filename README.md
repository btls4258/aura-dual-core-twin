# AURA：方舟对决 · 数字孪生桌游

实体 AURA 机器人桌游的 Web 控制台原型。默认使用两台虚拟 AURA，无需真机、手机摄像头或 DeepSeek 即可完整游玩。当前版本支持：

- Three.js 开放式战场与轻量化 GLB 模型
- 命中后在 AURA 或基地落点播放阵营色扩散光环与能量光柱
- 双阵营生命、基地、护盾、能量值和 7 类卡牌
- 双方独立洗牌、手动摸牌和完整的离线回合流程
- 玩家选牌、AURA 人格 Agent 裁决执行方式（DeepSeek 可选，本地人格兜底）
- Mac 摄像头二维码识别（原生 `BarcodeDetector`，附手动回退）
- 手机全局摄像头通过局域网 WebRTC 推流到 Mac，并在手机端使用 WASM 识别 AprilTag
- 双 AURA 局域网连接、视觉闭环实体路径执行、紧急停止与实体/虚拟混合模式

## 启动

项目要求 Node.js 22.13 或更高版本。

```bash
npm install
npm run dev
```

打开 `http://localhost:3000`。`npm run dev` 还会启动可选的手机摄像头网关，并在终端打印类似下面的地址：

```text
https://<Mac 局域网 IP>:8443/phone-camera.html?room=aura
```

手机和运行本项目的电脑必须连接同一局域网。首次访问手机地址时需允许本地测试证书，再允许摄像头权限。

生产模式或 AuraOS Skill 会使用以下命令：

```bash
npm ci
npm run build
npm run start
```

此模式只启动游戏 Web 服务；手机摄像头仍是可选扩展，可按需另行运行 `npm run dev:camera`。

## 洗牌与摸牌

- 每个阵营使用独立的 23 张牌库，开始新对局时分别随机洗牌。
- 双方各抽 5 张起始手牌，因此每局和双方拿到的牌都会不同。
- 每个回合最多主动摸 2 张，手牌上限为 8 张；结束回合后轮到对方并重置摸牌次数与能量值。
- 不连接实体机器人时，生命、卡牌、胜负和回合全部由本地规则引擎处理，可以完整游玩。
- 接入机器人后，`RobotTransport` 只负责把已通过规则校验的动作映射到实体 AURA，网页仍是数字孪生与裁判界面。

## AURA 人格 Agent

行动控制栏可以随时选择两种决策模式：

- **人格裁决**：玩家只选择卡牌，AURA 人格决定是否执行、目标与移动路线。
- **玩家直控**：恢复传统玩法；移动时由玩家点击地图落点，其余卡牌由玩家确认后立即执行。

同一回合不限制移动、攻击、修复、护盾或干扰卡的使用次数；只要手中有牌且能量足够，就可以继续打出。每张移动卡的单次路线上限为 70 cm，Agent 可以根据人格选择更短的合法路线。

移动 Agent 会从 16 个方向生成候选落点，并由 A* 规划直线或曲线绕障路线。战术评分会综合向敌方基地的推进量、当前手牌可用射程、己方基地距离和侧翼幅度，再从排名前三的路线中按人格择优。系统会记录每方最近三次移动并惩罚重复通道；破阵者优先绕障逼近敌方核心，守望者维持有效交战距离，演算师抢占手牌的最佳射程，逐风者偏爱仍能继续推进的新侧翼。

三档攻击射程分别为 35 / 55 / 75 cm，开局两台 AURA 相距约 116 cm，因此必须先移动才能攻击。射程不足时攻击卡直接作废并进入弃牌堆，同时照常消耗能量；这属于规则失败，不是人格拒绝。

当 AURA 生命降为 0 时进入失能状态：不能移动、摸牌或打出任何卡牌，只能消耗 10 点基地生命进行重构并恢复到 20 点生命；如果无法重构，仍可结束回合。

玩家只决定打出哪张卡牌，AURA 人格负责决定是否接受，以及具体如何执行：

- 移动卡：从前端碰撞与边界校验通过的路线中选择落点。
- 攻击卡：综合敌方 AURA、护盾、基地生命与剩余重构次数动态选择目标；可击毁基地时优先终结，可击毁 AURA 时会考虑迫使对方消耗基地生命重构。
- 修复卡：决定修复己方 AURA 或基地。
- 护盾与干扰卡：根据人格和战况接受或拒绝。

内置四种可切换人格：偏进攻的“破阵者”、偏防守的“守望者”、偏最优解的“演算师”和偏侧翼变化的“逐风者”。玩家一旦把卡牌提交给 Agent 裁决，就视为已经打出：无论 Agent 接受还是拒绝，卡牌都会进入弃牌堆并照常消耗能量。未配置云端模型时会使用毫秒级本地人格规则，因此离线对局不受影响。

如需启用 DeepSeek，请只在服务端配置密钥：

```bash
cp .env.example .env.local
# 编辑 .env.local，填写轮换后的 DEEPSEEK_API_KEY
npm run dev
```

`.env.local` 已被 Git 忽略，密钥不会进入浏览器代码。云端请求设置了 3 秒短超时，超时、断网或返回格式无效时会立即退回本地人格规则。

## 卡牌二维码格式

实体卡牌上的正式二维码直接编码中文卡牌名称，例如 `极昼疾行`、`曙光脉冲`。扫描时系统会从当前行动方手牌中匹配同类型卡牌，不需要把实体卡绑定到红方或蓝方。

调试时仍支持 JSON：

```json
{"version":"0.1","faction":"red","cardType":"move","instanceId":"red-move-01"}
```

也支持紧凑格式：`RED-MOVE-01`。卡牌类型为 `move`、`pulse`、`beam`、`pierce`、`repair`、`shield`、`jam`。

## 接口边界

- `app/lib/robot-transport.ts`：机器人连接与指令发送接口；默认使用 Mock，也可连接两台 AuraOS 实体机器人。
- `app/lib/protocol.ts`：卡牌、感知、世界状态、机器人指令和急停事件主题。
- 手机负责采集视频并在本地识别 AprilTag 36h11；Mac 根据 ID 4、5、6、7 完成场地标定，根据 ID 0、1 同步两台 AURA 位姿。
- 网页右上角的“连接机器人”可分别填写赤曜与蓝穹 AURA 地址，默认示例为 `http://192.168.31.31:8765` 和 `http://192.168.31.32:8765`。机器人端需启动 AuraOS daemon、监听局域网地址并保持底盘串口在线。
- 两个阵营可分别选择“实体机器人”或“虚拟机器人”，支持双实体、单实体 + 单虚拟、双虚拟三种组合。选择实体的一侧通过 `/api/motion/status` 与 `/api/motion/telemetry` 后独立进入联机；连接失败的一侧保持虚拟，已经连接的另一侧不受影响。
- 实体移动会沿前端 A* 已验证的路径调用 `/api/motion/target_yaw` 与 `/api/motion/move_distance`。视觉正常时每次最多前进 8 cm 后校正；视觉中断时允许最多三段、每段最多 30 cm 的有限恢复。执行异常会停车并保持实体连接；“紧急停止”调用 `/api/motion/stop`。
- 连接时默认认为两台机器人位于各自基地，黑色正面相对。当前航向会被读取为本局零点；实际测试前仍应架空轮组或清空场地，先用短距离移动验证正方向和尺寸标定。
